# 0001 · Plan and v0.1 scope

Status: accepted, 2026-11-11 (grilling with Nik).

## Why

A portfolio project for job applications (frontend / full-stack, Vue and Nuxt) that is useful and has an angle of its own. The git-learning market is crowded (LearnGitBranching, Gitvana, Oh My Git!, Githug, GitQuest); the angle is **simulated teammates** (others change `origin` while you work), later **real-world disaster scenarios** and **workflow tracks**, and a terminal plus graph that update together.

## Decisions

- **Brand**: Grindstone is the developer practice app; Git is its first track. One repo from the start, no rename later. The scenario engine keeps git-specific code apart from what every track shares (levels, goals, hints, debrief, progress). No skill radar or daily sessions until a second track exists.
- **Audience**: developers who know `add`/`commit`/`push` but fear rebase, conflicts and keeping up with teammates. English UI, i18n-ready.
- **Engine**: Grindstone's own git model in TypeScript, not isomorphic-git (it has no `rebase`, and its `merge` leaves the working tree as it was). See `0002-git-model.md`.
- **Stack**: nuxt_template as a static SPA; Caddy on Hetzner at `grindstone.dkiessling.de` (`grindstone.dev`, `.app`, `.io` are taken; a domain can come later). Public repo, MIT.
- **Terminal**: own Vue component (output lines, one input line, ↑/↓ history, Tab completion for commands and branch names); not xterm.js: no TTY needed, lighter, accessible, easy to test.
- **Shell**: `ls`, `cat`, `echo "x" > f`, `echo >> f`, `rm`, `touch`, `edit <file>` (opens an editor panel, used for conflicts).
- **Graph**: own SVG component; one lane per branch, `origin/*` outlined, HEAD marked; animates new and moved commits.
- **Layout**: desktop first: goals and level text left, terminal centre, graph right (graph above the terminal on narrower screens), hints behind a button, debrief dialog. Phones get a stacked layout that works, with a "best with a keyboard" note.
- **Levels**: fixed order, nothing hard-locked; Reset level and `undo`. Progress in localStorage.
- **Analytics**: none in v0.1; self-hosted Umami (cookieless) in the first patch after launch.
- **Tests**: git model test-first in Vitest; every level's solution replayed; one Playwright run plays level 1.

## v0.1 scope (about one week)

Six levels: 1 commit, 2 branch, 3 merge, 4 merge conflict, 5 rebase, 6 teammate sync.

Level 6: you are on `feature/login` with 2 commits. Right before your first `push`, Anna pushes 2 commits to `main`, one touching the same file. Goals: `feature/login` rebased onto `origin/main`, conflict resolved, pushed with `--force-with-lease`, no merge commits. Debrief: rebase vs. merge for feature branches, `--force-with-lease` vs. `--force`.

Commands in v0.1: `init, status, add, commit (-m, --amend), log (--oneline, --graph, --all), branch, switch/checkout (-b), merge, rebase (--continue, --abort), fetch, pull (--rebase), push (--force-with-lease), diff (basic)`.

## After v0.1 (patch releases)

Levels 7–10: cherry-pick, reset vs. revert, amend, stash (with their commands). Then Umami. Later: disaster track, workflow tracks (GitFlow, trunk-based, release branches), visual drag-and-drop mode, team onboarding mode (scenarios as data files), multiplayer merge-conflict arena, further tracks.

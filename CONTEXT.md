# Context: Grindstone glossary

- **Track**: one skill area of the app, with its own page (`/git`) and its levels in chapters. *Live* tracks are playable (Git, Debugging); *coming* tracks (Working with AI, Web fundamentals, Framework deep dives) are listed on the home page but have no levels yet.
- **Chapter**: an ordered group of levels inside a track, with a number, a one-line description and a colour from the branch palette (Git: Basics, Branching, Merging, Rewriting history, Teamwork & remotes, Undo & recovery, Disasters, Workflows). All chapters are open, nothing is locked. A chapter without levels is *coming*.
- **Level** (also *entry*): one thing to solve in a track, of one of two kinds: a scenario or a practice task. Counts ("n of N solved"), next up and Continue include both kinds.
- **Scenario**: a level with a short story, goals, three hints and a debrief, written as one TypeScript file (setup, goals, teammate events, hints, debrief, solution). Its **number** is `chapter.position` counting scenarios only (`1.2`, `3.2`), derived from where it is listed.
- **Practice task** ("Practice" in the UI, never "drill"): a short level of one to three commands (~30 s) that trains one scenario: one task line, one goal (a few at most), one hint, a one-line why, then Next and Again; no story, no debrief, no number. It is listed right after its scenario and drawn on a side branch forking off the scenario's dot.
- **Difficulty**: 1 to 3, shown as filled dots; every level also has an estimated **time**.
- **Next up**: the first unsolved level of a track, in play order (chapter by chapter; a scenario, then its practice tasks).
- **Continue**: the one button back into practice: the level you last played while it is unsolved, else next up; with nothing unsolved left, a level marked "practise again". Otherwise there is nothing to continue.
- **Best run**: in Git, the fewest commands you solved a level in (ties broken by fewest hints); in Debugging, the fewest hints, then the fewest reloads, kept next to your **latest run**; replaying never costs anything.
- **Practise again**: a flag you set on a solved level ("solved, but I don't own it yet"); Continue and the chapter menu offer flagged levels once nothing new is left.
- **Reset**: clears solved, best and latest run, the "practise again" flag and last played for one level ("Mark as not solved"), a chapter, a track or everything, always after a confirmation.
- **Environment**: what a track's levels run in and are checked against: Git's is the git model with its terminal and graph, Debugging's the sandbox. The shared level core (levels, goals, hints, progress, Continue, radar) works the same over any environment (ADR 0007).
- **Setup**: the starting state of a level (local repo, `origin`, files, current branch), built with the setup builder.
- **Goal**: a named check over the state, shown as one line of the live checklist. A level is solved when every goal passes.
- **Hint**: three per scenario (from a nudge to the exact command, or in Debugging to the exact line), one per practice task.
- **Debrief**: the short text shown when a scenario is solved, explaining *why* the solution works (a practice task shows a one-line why instead).
- **Solution**: the steps that solve a level (git: command lines, and saves of the file git opens in the editor during `git rebase -i`; Debugging: file edits, a reload, or the click of a find task); tests replay them (Debugging's in a real browser).
- **Git model**: Grindstone's own simulation of git (objects, refs, HEAD, index, working tree), not real git.
- **Origin**: the simulated remote repository. Your repo sees it only through `fetch`, `pull` and `push`; teammates write only to it.
- **Teammate**: a scripted colleague (e.g. Anna) who acts on `origin`.
- **Teammate event**: one thing a teammate does (push commits, force-push, merge a pull request on origin), fired by a **trigger**: after N of your commands, right before a given command, or once a check on the state passes (your branch reached origin). In Debugging's Incidents the same events are a **colleague**'s messages (see Colleague event).
- **Shell**: the small fake shell around git (`ls`, `cat`, `echo >`, `echo >>`, `rm`, `touch`, `edit`).
- **Graph**: the SVG commit graph that redraws after every command; local branches solid, `origin/*` outlined.
- **Progress**: per level: solved, best run, latest run, "practise again", when you last played it (for Continue). Stored in localStorage; the About page downloads it as a backup file and loads it back.
- **Ignored file**: an untracked file a `.gitignore` names; `status` and `git add .` leave it out.
- **Skill radar**: one per track, an axis per chapter showing the share of its levels you solved (a solve that needed the last hint counts half). On the track page and in the debrief (ADR 0007).
- **Sandbox**: in the Debugging track, the sealed iframe in which a level's real app (HTML, CSS, plain JavaScript) runs; Grindstone's panels read from it.
- **Fake backend**: the scripted answers a Debugging level gives its app's requests (data, errors, delays, a failed connection), so every run is the same. It answers `fetch` inside the sealed frame, so no request ever leaves it; the app still gets real `Response` objects. Each load of the app starts it over.
- **Route**: one thing the fake backend answers: a method and a path (on the shop's own address, or a whole URL on another origin) to an answer, or to a list of answers given call by call (the last one repeats). A route can be limited to requests whose query or body matches a pattern, so an answer (and how long it takes) can depend on the request.
- **Shop's own address** (*origin*): `https://cornerbakery.shop`, where the app's page lives. A request to another origin is refused by **CORS** unless the route's answer allows the shop (`Access-Control-Allow-Origin`), as a browser would; its reason shows only in the Console.
- **Network panel**: the Debugging panel, next to the Console in levels with a fake backend, that lists the app's requests (method, name, status, time); selecting one shows what was sent and what came back, as text. Its **Sent from** link (the browser's *initiator*) opens the line that sent the request.
- **Elements panel**: the Debugging panel, next to the Console in chapter 3's levels, that shows the app's DOM as a tree and, for the selected element, the CSS rules that match it in cascade order (what lost struck through, each linked to its line), what it inherits, its box and a few computed values. Read-only: fixes happen in the code. Its tree is a **snapshot**, taken after each load, on Refresh and on a pick.
- **Pick** (*pick mode*): in the Elements panel, the next click in the app selects the element it lands on (what is really on top there, even a transparent one) instead of reaching the app.
- **Cascade**: how the browser decides which declaration wins when several rules set the same property: !important, the style attribute, then **specificity** (ids, then classes, then element names), then the later rule. What an element doesn't set itself it may **inherit** from its parent (colour, fonts, `pointer-events` …).
- **Console**: the Debugging panel with the app's logs and errors, clickable stack traces and an input line that runs an expression inside the app (a top-level `await` too).
- **Reload**: restarting a Debugging level's app after an edit; the fewest reloads (after the fewest hints) make the best run there.
- **Bridge**: the small script Grindstone puts first into a Debugging app's sealed frame; it reports the app's console calls and errors, runs Console input and the probes, and is the only way the frame talks to Grindstone.
- **Check run**: what a Reload starts besides restarting the app you see: the saved files run once more in a hidden sealed frame as wide as a phone (390 px), the level's probes click and read, and what that run saw decides the goals. A probe that asks for another width (a laptop's 1024 px) runs in a frame of that width too.
- **Probe**: a scripted look at a Debugging app during the check run, e.g. "click Add on the croissant, then read the basket counter", "double-click Order, then count the `POST /api/orders` requests", or, from the layout, "what does a tap on the middle of Order land on" and "is the Order bar visible on a phone", or like a customer who types on: "type `cro`, pause, type `croissant`, then read the results once every answer is in", or in chapter 6 what it cost: "type `croissant` letter by letter, press Enter, then count the search requests", "add a croissant, then count the nodes the menu changed". Goals read probe values, never the code.
- **Find** and **quick fix**: the two kinds of Debugging practice task. A find task is answered by clicking the right line in the editor (read-only), the right frame in a stack trace, a request's Sent from link, a rule's link in the Elements panel, or in chapter 5 a frame of the Debugger's Call stack or its Answer button at a recorded step, or in chapter 7 a frame in a log line's stack, a changed line of a deploy's diff, or a deploy itself ("Answer: b7e41d0"); a wrong click says why it isn't that one. A quick fix is one line to change, then Save and Reload (in chapter 7 it can be a Roll back, then Reload).
- **Debugger**: the Debugging panel, next to the Console in chapter 5's levels, that records a run of the app and steps through it: breakpoints, Resume, Step over / into / out / back, a scrubber, the Scope and the Call stack. Nothing is ever paused (a sealed frame can't be paused safely), and the panel says so.
- **Recording** (*recorded run*): what Record makes: the app reloads with its code **instrumented** (rewritten before it runs so every statement reports a step, without moving a line or changing what it does), you use it, Stop ends it (or a cap: 2000 steps, or values too slow to read). A Reload, Reset or a new Record ends it; the check runs never run instrumented code, except a chapter 6 check run whose probes read the **work**, which counts.
- **Step**: one moment of a recording: the statement about to run (its file and line), the call stack and the values the statement could see, read just before it ran. **Step over** goes to the next step of the same call (after an `await`, where the function goes on), **step into** to the very next step, **step out** to the first step after the call ended, **step back** to the step before.
- **Breakpoint**: a line the Debugger stops at when you Resume (forward or back), set by clicking a line number in Code (or Ctrl/Cmd+B); it stops once each time the line runs. A **conditional breakpoint** stops only where its condition (`price < 1`) holds on that step's recorded values; Grindstone evaluates it itself, no app code runs.
- **Scope**: the Debugger's list of the variables a step could see, innermost first (Block, Local with `this`, Closure, Module), each with its value at that moment; objects open into their entries (a few levels deep, getters never called).
- **Call stack**: the Debugger's list of calls at a step, the running function on top, each with the line it was at; an async function back from an `await` shows the calls that started it below an "async" line. Clicking a frame shows its line and its Scope as of its own last step.
- **Performance panel**: the Debugging panel, next to the Console in chapter 6's levels, that profiles a run of the app: Record, use the app, Stop; then how often each function ran and its work, what the code changed on the page, and the requests on the server's clock, for the whole run or one action at a time. Counted, not timed, so the numbers are the same in every browser, and the panel says so.
- **Profile** (*counted run*): what Record makes in the Performance panel: the app reloads with its code instrumented to **count** (chapter 5's instrumentation; no values read), and what it counts is grouped by action. A Reload, Reset or a new Record ends it.
- **Work** (*unit of work*): Grindstone's cost model for chapter 6: one unit per statement of the app's code that ran (a built-in it calls counts as part of that statement). **Self** is a function's own units, **total** its units with everything it called.
- **Render**: a call of a function whose own statements changed the page; its **nodes** are the elements and texts it added or removed and the attributes and texts it set.
- **Action**: in a profile, the page's load or one thing the customer did (a click, a letter typed, a change, Enter); it counts everything that ran from it until the next one.
- **Server's clock** (*server time*): time that moves only when an answer arrives, to when its request went out plus its scripted delay. On it, requests that wait for each other show as a **waterfall** (stairs: each sent once the one before had answered), requests sent together side by side; a **repeat** is a request the page already made, made again ("the same request again"). Chapter 7's log lines are timed on it too, from the moment the app loaded (`09:41:00.000` plus the delays).
- **Incident**: in chapter 7, something broken for real customers that a colleague reports; you find the cause in the server's logs and the shop's deploys, then fix forward or roll back.
- **Logs panel**: the Debugging panel, next to the Console in chapter 7's levels, with the shop server's **log lines**: what it logged before you came (the incident so far), then for each request of the app you see the lines its answer logged and its **access line** (`POST /api/orders 500 Internal Server Error · 40 ms`). Each line has its time on the server's clock, a level (info, warn, error), the route, the request id and the message, maybe a **stack** (server code as text; a frame in one of the app's files links its line). Filter by level and by text.
- **Request id** (*reference*): the server's name for a request (`req-4128`), sent back as the `x-request-id` header; a page may show it to the customer, the log lines name it, and in the Logs panel it opens that request in the Network panel (this load's requests only).
- **Deploy**: one change that went live on the shop: an id (`b7e41d0`), who, when, why and the files it left. The **live** deploy is the newest; a level's starting files are its files.
- **Deploys panel**: the Debugging panel, next to the Console in chapter 7's levels, that lists the shop's last deploys, newest first, each with its **diff** (git's unified diff); a changed line opens where it is in your code now. It also says which version your saved code is.
- **Roll back**: putting an earlier deploy's files into the editor, saved, after a confirmation that says which files change (**Back to live** does it for the newest); Reload runs them. One counted action, not a reload. When it replaced saved code of your own (no deploy's), **Undo roll back** brings that back. **Fix forward**: fixing the cause in the code instead, so what the deploy brought stays.
- **Colleague event**: in chapter 7, a colleague's message during play: the **report** a scenario opens with, and one more on a generic trigger: after a number of counted actions, or after a **fix that did not work** (a reload of changed code whose check failed). Never on a timer; the level panel lists them (Messages) and reads a new one out.
